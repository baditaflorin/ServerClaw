## Context

Phase 5 (`make doctor`) surfaces 4/7 non-zero drift signals on the live
repo. Each signal carries a `heal_command` field, but the heal commands
are advisory pointers — there's no orchestrator that runs them, and
two of the signals have known accuracy gaps:

- **`safe_to_refresh: 0`** — the role-lookup heuristic in Phase 4.3
  (`scripts/refresh_safe_receipts.py`) only probes
  `<service>` / `<service>_runtime` / `<service>_postgres`. Real role
  names (`langfuse_runtime`, `agent_coordination`, etc.) often map to
  service-registry entries with explicit `host_group` and `roles`
  metadata that the helper ignores. Result: 61 stale receipts get
  classified as "unknown" because the heuristic can't find their roles.
- **`validator_gaps: 14`** — 14 of 30 validators lack docstrings.
  `make doctor` flags them but the gap stays open until somebody
  hand-writes 14 docstrings.

Phase 6 ships three self-healing actions that turn the doctor's
"here's the drift" output into "the drift is fixed":

1. Registry-driven role lookup in `refresh_safe_receipts.py` — unlock
   real safe-to-refresh classifications.
2. `scripts/heal.py` + `make heal` orchestrator — runs every doctor
   heal command in sequence, dry-run by default.
3. Validator docstring backfill — auto-generate one-line docstrings
   from existing comment headers / function names for the 14 validators
   missing them.

---

## Decision

### Phase 6.1 — Registry-driven role lookup

Extend `scripts/refresh_safe_receipts.py::candidate_role_paths` to
load `inventory/group_vars/all/platform_services.yml`. For each
service, the helper now consults:

  1. The service registry's `<svc>.roles` field (when present).
  2. The conventional `<svc>` / `<svc>_runtime` / `<svc>_postgres`
     path probes (existing behaviour, unchanged).

This collapses the "unknown — no matching role directory" bucket
(currently 61 entries) and lets the safe-to-refresh classifier give
real signal.

A new test pins the registry-lookup path so a future schema change
breaks tests rather than silently regressing the count.

### Phase 6.2 — `scripts/heal.py` + `make heal`

A thin orchestrator that:

1. Runs `scripts/doctor.py --json` to enumerate signals.
2. For each signal with `count > 0` AND a non-null `heal_command`,
   prints "would run: `<command>`" (dry-run default).
3. With `--apply`, executes each heal command sequentially, capturing
   stdout/stderr, and emits a per-signal pass/fail summary.

Default mode is dry-run because heal commands can mutate disk state
(receipt-refresh writes to `versions/stack.yaml`). `--apply` is a
deliberate gesture.

### Phase 6.3 — Validator docstring backfill

`scripts/heal_validator_docstrings.py` walks the validator catalogue,
finds entries with `purpose == "(no docstring)"`, and proposes a
one-line docstring synthesised from:

- The script's existing top comment (if any).
- The first non-trivial line of the file (skipping shebangs).
- The file's name (e.g. `validate_dns_declarations.py` →
  "Validate DNS declarations.").

Default mode is dry-run; `--apply` writes the synthesised docstrings
to disk. Each docstring includes a `# TODO: refine — auto-generated by
heal_validator_docstrings.py` so reviewers know to upgrade them. The
catalogue regenerator picks the new docstrings up automatically.

## Acceptance Criteria

- `scripts/refresh_safe_receipts.py` consults `platform_service_registry`
  for role lookup; the live `safe_to_refresh` count rises above 0 for
  any service whose registry-listed roles are unchanged since the
  receipt date.
- `make heal` runs `doctor.py --json`, lists every heal command, and
  exits 0 in dry-run mode regardless of doctor signals.
- `scripts/heal_validator_docstrings.py --apply` reduces the
  `without_docstring` count in `build/validator-catalogue.yaml` by
  at least 10.
