## Context

Phases 4–10 closed every observable self-healing gap. The next four
gaps are *ergonomic* — they concern how cheaply the next agent can pick
up context, draft a PR, or read derived state without paying an LLM
round-trip per query. The bar: any view an agent reads more than once
per session should be a CPU-cached file, not a re-run of probes.

Four discrete misses identified during Phase 9 retrospective:

1. **Onboarding cards** — `make discover` writes service-catalog.yaml
   but no per-service readable artifact. Every "what does service X
   look like" query forces an LLM to grep four files.
2. **Workstream SQLite index** — `workstreams.yaml` is 2.7 MB; loading
   the full registry just to find one entry burns prompt tokens.
3. **Auto-PR-body** — every release PR is hand-written. Same five
   sections (summary, checklist, test plan, ADR ref, postmortem ref)
   recur; agents waste tokens drafting them.
4. **Context packs** — agents starting on a workstream re-read the same
   ADR + workstream + relevant runbook for every fresh session.

## Decision

Ship four CPU-only primitives that materialise these views ahead of
time so agents read pre-rendered artifacts:

### Phase 11.1 — `scripts/generate_service_cards.py`

Walks `catalog/services/<svc>/service.yaml` + cross-references
`platform_service_registry` and writes one Markdown file per service to
`build/service-cards/<svc>.md`. Sections: identity (host group, port,
domain, registry status), endpoints, health probes, owners, ADR
back-refs, recent live-apply receipts. Idempotent with `--check`.

### Phase 11.2 — `scripts/build_workstream_db.py`

Reads `workstreams.yaml` and writes `build/workstreams.sqlite3` with
indexed columns (id, status, owner, adr, branch, plane_issue_id). Every
agent querying "what's in flight for service X" or "which workstreams
depend on ADR 0470" runs SQL against the cached DB instead of parsing
2.7 MB of YAML. `--check` mode verifies freshness vs HEAD of
workstreams.yaml.

### Phase 11.3 — `scripts/generate_pr_body.py`

Inspects the staged diff + most recent ADR/workstream entries and
writes a draft PR body to stdout (or `--write` to
`build/pr-body-draft.md`). Sections derived from real state:
`## Summary` from changelog Unreleased; `## Release checklist` from
file presence (VERSION, release-notes/, platform-manifest.json);
`## Test plan` from receipts/health-probes/ + receipts/gate-runs/.
Agents redact + extend; baseline draft is free.

### Phase 11.4 — `scripts/generate_context_packs.py`

For every active workstream, materialises a single
`build/context-packs/<ws-id>.md` containing: workstream YAML body, the
referenced ADR Markdown, the relevant section of the changelog, and a
pointer to recent commits touching the shared_surfaces. Cold-start
agents read one file and have full context, instead of opening four.
Regenerated by post-merge hook.

## Consequences

- Four new artifacts under `build/` (gitignored) — operators run `make
  refresh-cpu-views` to regenerate everything.
- One new `make` target wires all four into a single command.
- Doctor surfaces freshness for each (mirroring ADR 0465's snapshot
  freshness probe).
- 30+ new tests covering the four scripts in isolation.

## What this unblocks

- A new agent on a fresh worktree reads `build/context-packs/<ws-id>.md`
  in one shot and is up to speed on any active workstream.
- "What's the status of service X" returns from a SQL query in 50 ms
  instead of a 4-file grep + LLM synthesis.
- Release PR bodies write themselves from real artifacts.

## Future work (deferred)

- Wire the context packs into the autonomous loop's onboarding step
  (Phase 12+).
- Promote `build_workstream_db.py` to a daemon that watches
  `workstreams.yaml` for changes (currently regenerates on demand).
