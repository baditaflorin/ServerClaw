## Context

After Phase 6, `make doctor` shows **3/7 signals non-zero** on the
live repo:

```
[!]  stale_receipts      72/187 stale at 30d window
[ok] safe_to_refresh     0 receipts safe, 11 need converge re-run
[!]  dangling_surfaces   3 workstream(s) with dangling shared_surfaces
[ok] validator_gaps      30 validators; 0 missing docstring (was 14)
[ok] late_bound_defaults no late-bound defaults in role defaults
[ok] unreserved_adrs     436 ADR(s) (informational)
[!]  blocked_substrate   1 .gitkeep placeholder(s) in collection substrate

summary: 3/7 signal(s) non-zero
```

Two of the three remaining red signals are addressable from this
worktree without production access:

- **`dangling_surfaces: 3`** — three real path mismatches in other
  agents' workstreams, all forward-looking references (artifacts that
  haven't been generated yet, archived workstream paths the workstream
  hasn't moved to). The traceability validator currently has no way to
  distinguish "missing because broken" from "missing because pending".
- **`blocked_substrate: 1`** — `collections/ansible_collections/lv3/platform/molecule/.gitkeep`
  blocks ws-0446 phase 4 (Molecule scaffold expansion). Replacing the
  `.gitkeep` with a minimal `proxmox-fixture` driver stub unblocks the
  substrate even before the full driver lands.

The third red signal (`stale_receipts: 72/187`) is partially addressable:
the Phase 6.1 registry-lookup plumbing is in place but unused because
`platform_service_registry` entries don't yet declare a `roles:` field.
Backfilling that field for the 11 `needs_review` services
demonstrates the registry-lookup path end-to-end and shrinks the
"unknown" bucket from 61 toward the 11 real-work-needed services.

Phase 7 ships four deliverables that close the doctor loop on
everything reachable from this worktree.

## Decision

### Phase 7.1 — `# pending:` marker in the traceability validator

Extend `scripts/generate_traceability.py` to recognise an inline
`# pending: <reason>` comment on a `shared_surfaces` list entry. When
present, the entry is excluded from the dangling-surface check (the
file legitimately doesn't exist yet, but the reason is documented).
The marker mirrors the `# late-bound-allow:` pattern from Phase 1
(ADR 0445) — same shape, same audit semantics.

A short audit pass against the live workstream registry can then
either confirm the entries are pending-with-reason (annotate) or
genuinely broken (delete / fix path).

### Phase 7.2 — Annotate the three dangling-surface workstreams

Three concrete fixes, one per workstream:

- **ws-0377-repo-intake-subdomain**: `config/generated/nginx-upstreams.yaml`
  is a generated artifact that doesn't exist on disk yet. Annotate
  with `# pending: generated by future nginx-upstream generator`.
- **ws-0396-live-apply**: `workstreams/archive/2026/ws-0396-live-apply.yaml`
  is the path the workstream will move to after archival. Annotate
  with `# pending: forecast — workstream not yet archived`.
- **ws-realtime-dynamic-children**: `playbooks/realtime.yml` and
  `roles/netdata_runtime/defaults/main.yml` are aspirational —
  netdata was removed (ADR 0401). Annotate both with
  `# pending: blocked on netdata replacement decision (ADR 0401)`.

After the annotations, `make doctor` reports `dangling_surfaces: 0`
and the validator continues to surface any newly-introduced dangling
path.

### Phase 7.3 — Replace `.gitkeep` with a stub proxmox-fixture driver

Drop a minimal create + destroy pair under
`collections/.../molecule/drivers/proxmox-fixture/`. The stubs do
nothing executable today (no Proxmox API calls — that's a separate
workstream) but they exist as YAML scaffolds with the expected
`hosts: localhost` shape Molecule expects. Removes the `.gitkeep`,
unblocks ws-0446 phase 4 from a substrate perspective, and
documents the missing implementation with a clear `# TODO` block.

`make doctor` then reports `blocked_substrate: 0`.

### Phase 7.4 — Backfill `roles:` for needs-review services

For each of the 11 services currently classified as `needs_review`,
add a `roles:` list to its `platform_service_registry` entry naming
the actual role(s) (e.g. `langfuse_runtime`, `langfuse_postgres`).
This activates the Phase 6.1 registry-lookup path end-to-end. The
unknown bucket should shrink as a side effect — services whose
heuristic-derived role names didn't match disk now have explicit
mappings.

Acceptance: at least 5 of the 11 needs-review services have explicit
`roles:` declarations after this phase. The remaining 6 may have
roles that don't exist on disk (and would still classify as unknown,
correctly).

## Acceptance Criteria

- `make doctor` reports `dangling_surfaces: 0`.
- `make doctor` reports `blocked_substrate: 0`.
- At least 5 services in `inventory/group_vars/all/platform_services.yml`
  carry an explicit `roles:` field.
- Tests cover: pending-marker filter; stub-driver YAML loads under
  Molecule schema; registry-lookup integration with new roles entries.
