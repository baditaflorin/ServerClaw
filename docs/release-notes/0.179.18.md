# Release 0.179.18

- Date: 2026-04-28

## Summary
- ADR 0457 + ws-0457: host-pinning Phase 1 — `proxmox_guests[*].deployment_owner` data model + `scripts/host_pinning_check.py` audit primitive. Closes Slice D from the ws-0448 postmortem (the underlying class of bug behind the lv3 ↔ 0fork `oauth2-proxy@4180` port collision). Optional field; absent = legacy shared-VM behavior. The standalone audit script reports drift (declared_owner != declaring deployment) and supports `--all`, `--host`, `--cross`, `--json`. 12 new tests. Phase 2 (role-side enforcement) deferred to a follow-up so role behavior changes can land per-role with author review.

## Platform Impact
- No changes to existing role tasks. Topologies that opt into `deployment_owner` get a new audit signal; topologies that don't are unchanged.
- The script is a candidate for the pre-push gate's advisory lane in a follow-up workstream.

## Upgrade Guide
- Optional: add `deployment_owner: <slug>` to each `proxmox_guests[*]` entry in `.local/deployments/<slug>/topology.yml`, then run `python3 scripts/host_pinning_check.py --all` to confirm pinning.
