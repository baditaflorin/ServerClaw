# Release 0.179.11

- Date: 2026-04-28

## Summary
- ADR 0448 + ws-0448: per-deployment connection registry + `run_with_deployment.sh` wrapper + topology `role` auto-fill. `.local/deployments/<slug>/connection.yml` now carries each deployment's Proxmox-host SSH metadata as committed-shape data; `scripts/deployment.py connection --slug <slug> --format=env` emits the `LV3_PROXMOX_HOST_*`, `LV3_BOOTSTRAP_SSH_PRIVATE_KEY`, and `PLATFORM_IDENTITY_OVERLAY` block. `scripts/run_with_deployment.sh` wraps any inner command (`make`, `ansible-playbook`) with that env. `scripts/generate_platform_vars.py` defaults `proxmox_guests[*].role` to `name` when absent so per-deployment topology overlays stay minimal. Closes the operator-surface gap left by ws-0445 phase 1.
- Workstream registry hygiene: every workstream YAML now quotes its `adr` field (`adr: "0447"` instead of `adr: 0447`). YAML's octal-int parsing was silently coercing values like `0447` → `295`, breaking `scripts/canonical_truth.py --check`.

## Platform Impact
- No service convergence required. Operator-only ergonomics: `scripts/run_with_deployment.sh --deployment <slug> -- <cmd>` replaces the per-deployment `LV3_PROXMOX_HOST_ADDR`/`PORT`/`SSH_PRIVATE_KEY` env-var dance.
- `inventory/group_vars/platform.yml` regeneration is byte-identical for existing deployments (auto-fill is a no-op when `role` is already set).

## Upgrade Guide
- For each existing deployment, drop a `connection.yml` next to the existing `identity.yml` / `topology.yml` / `profile.yml`. Schema is at `config/contracts/deployment-v1/connection.schema.json`. Sample under `docs/adr/0448-*.md`.
