# Release 0.179.20

- Date: 2026-04-29

## Summary
- ADR 0457 Phase 2 + ws-0459: role-side host-pinning enforcement. New `lv3.platform.host_pinning_guard` role refuses converge when the target host's `proxmox_guests[*].deployment_owner` points at a different deployment than the active slug. Resolves active slug from `active_deployment_slug` extra-var → `$DEPLOYMENT` env → `.local/active-deployment` file. Wired into `playbooks/public-edge.yml` as the first role. Closes the lv3 ↔ 0fork `oauth2-proxy@4180` collision class of bug at converge time rather than at incident time. 9 tests (5 structure + 4 behavioural via `ansible-playbook --check` on synthetic inventories).

## Platform Impact
- `make configure-edge-publication` (and any direct invocation of `playbooks/public-edge.yml`) now fails fast if the target host is pinned to a deployment other than the one being converged.
- Single-deployment installations (no `deployment_owner` set on any guest) are unaffected — the guard skips silently.
- Operators who legitimately need to bypass: pass `-e host_pinning_guard_enabled=false` (kill switch). Documented in `defaults/main.yml`. Production should not use this.
- Other playbooks (`ops-portal.yml`, `keycloak.yml`, etc.) are not yet wired — per-playbook owner opt-in.

## Upgrade Guide
- Set `active_deployment_slug=<slug>` (or write `.local/active-deployment` / export `$DEPLOYMENT`) before any `make converge-*` invocation that targets a multi-deployment host.
- Optional: populate `proxmox_guests[*].deployment_owner` in your topology to opt into enforcement.
