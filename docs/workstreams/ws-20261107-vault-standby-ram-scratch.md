# Vault standby courier scratch

The two-minute standby courier stages two online SQLite backups before streaming them. The deployed sender and its timer matched private source `000cfa12313a67df47cc4984bac120b4aa08ad50`. The two logical database sizes totalled 339,066,880 bytes during diagnosis, within 16 KiB of the recurring 339,083,264-byte user-slice write burst. The separate five-minute encrypted replication service has its own schedule and scratch path.

The sender now requests one private, no-swap 512 MiB tmpfs per database export, with a 768 MiB memory limit and a 140-second runtime. The transient unit has a read-only system filesystem, no network access and a 16-task limit. It verifies the mount and memory limits, requires 2 GiB of available memory and accepts only a regular source database of up to 448 MiB before copying. The temporary snapshot is removed on exit and the transient mount namespace also disappears with the unit. The source database opens read-only and the existing SQLite backup retries and SSH receiver remain in place. An oversized snapshot fails and leaves the prior verified standby copy available.

Native preflight used a synthetic database through the existing source SSH and sudo route. It verified the memory limits, restored the row, and left the source host's regular `/tmp` mount intact. Local tests cover the existing transfer and receiver behavior, rejection of disk scratch, and integrity of a streamed synthetic WAL snapshot. The standalone encrypted replicas have their own restore and retention contract.

PR687 passed both primary checks and merged as `5da314fa69b5a626964a48d342f747d87f8c216f`; the merged-main check passed. On 2026-11-07 at 07:04:23 UTC the exact merged sender was installed under its existing native lock, between scheduled runs, with a private before-image. Scheduled runs at 07:05 and 07:07 UTC succeeded. The receiver checked the integrity and non-empty schema of both snapshots; both standby sync markers advanced, and the existing timer and success metric remained healthy.

In two comparable 135-second samples, guest block writes decreased from 494,264,320 to 169,340,928 bytes. The old sender created two disk scratch files totalling 339,894,272 logical bytes; the new sender created none. Other workload was active, so the total is a short-window observation rather than a NAND or fleet-wide estimate. The 512 MiB scratch filesystem and 448 MiB source size limit are explicit operational limits; existing stale or missing-sync alerts remain the failure signal if growth or low memory prevents a snapshot.
